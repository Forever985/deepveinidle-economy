价格桥：数据闭环全在本机，不经过 GitHub

## 用户的硬要求

> 「我希望 dvi-tools 更新市场数据通过以下两个途径：1. 一小时一次。2. 每次刷新页面都获取。
> 最终如何进入 dvi-economy 网站？localstorage 或者 cookie 等。总之，**在玩家自己的电脑上
> 就要能解决，不能还要兜个大圈子去 github 部署等等。**」

## 为什么必须这么设计

游戏在 `deepveinidle.com`，利润站在 `github.io` —— **跨域**。
localStorage / cookie / IndexedDB **都不跨源**，没有共同的本地存储可用。
而「提交进仓库再部署」链路太长：依赖网络、依赖凭据、依赖 CI。

**解法：用 File System Access API 做一个本机文件桥。**
dvi-tools 写 `dvi-prices.json`，利润站读**同一个文件** —— 两边各选一次即可，
之后闭环全在本机，不碰 GitHub。

## dvi-tools 侧（新增 src/price-bridge.js，版本 2026.10.03.10）

两条更新途径（正是用户要求的）：
1. **每次刷新页面** —— 订阅 `EVT.MARKET`，市场消息一到就**防抖 4 秒**后落盘
   （消息很密集，不防抖会写太频繁）
2. **每小时一次** —— 另有 30 分钟检查一次，超过 1 小时没写就强制刷新一次快照时间

落盘双写：先存 `GM_setValue`（跨刷新保留，页面刚开还没行情时可用），
若已连接文件则写入该文件。

四个菜单入口：
- 💰 立即抓一次价格
- 🔗 连接价格文件（给利润网站用）—— 选一次位置，之后自动写入
- 💾 下载价格文件（降级方式，给不支持 FSA 的浏览器）
- 📈 价格桥状态（是否连接、上次快照时间、是否过期）

build.py 新增注入点 `/*@DVI_PRICE_BRIDGE@*/`。
**位置很关键**：必须在 api 对象发布**之后**（它要用 api.bus / api.EVT / api.state），
仍在主干 IIFE 内部，与主干同生共死。

## 利润站侧（新增 stores/market.ts + views/PriceView.vue）

三个入口，全部落到 **localStorage**，之后完全离线可用：
1. **连接本机文件**（推荐）—— 选一次 `dvi-prices.json`，之后每次打开自动重读；
   会先 `queryPermission` 检查授权，失效时引导重新授权
2. **拖放** —— 把 json 拖到页面任意位置（整页监听 dragover/drop）
3. **粘贴 JSON** —— 文本框兜底

页面还给出**买卖价差排行**，并把「可成交量」并排显示 ——
价差大看着诱人，但挂单量只有 1 的物品价差再大也卖不掉一单。

File System Access 的句柄不能可靠跨会话持久化，所以本次会话内自动重读；
真正免重复选择靠浏览器自己的权限记忆。失效时用 localStorage 缓存顶着，不会白屏。

## 踩坑

- File System Access API 不在 TS 标准 lib 里，`showOpenFilePicker` /
  `queryPermission` 都会报类型错。统一走 window 索引访问拿，避免散落 @ts-expect-error。
- Vue 模板里给 textarea 写了两个 `style` 属性，编译直接失败。已合并。
