部署脚本：优先用系统代理 + 新增 bash 版发布器

实机部署过程中发现并修掉的问题：

1. **系统代理才是主力通道**
   之前只认 Watt Toolkit 的 hosts 劫持路线，但实测那东西没开时整条链路不通。
   而 Windows 的系统代理（本机 127.0.0.1:10808）一直是通的，git 只是没用上。
   现在优先读注册表里的 ProxyEnable/ProxyServer，没有才退回反代路线。
   —— 这也是为什么我一开始推不上去：脚本里没这条路。

2. **Node 派生子进程在这个环境会 EBUSY**
   publish-gh-pages.mjs 原本用 shell:true（要经过 cmd.exe），
   在受限环境里直接 EBUSY 失败。改为直接 spawn git.exe，并加了安装路径兜底。
   同时消掉了 shell 带来的参数转义告警（DEP0190）。

3. **新建分支时不能跑 git rm**
   orphan 分支建出来时仓库还没有任何提交，
   `git rm --cached .` 必然报 "pathspec did not match any files" 并返回非零，
   脚本把它当致命错误退出了（而且是静默退出，连错都没打）。
   现在只在克隆已有分支时才清理，失败时打印是哪条命令。

4. **bash 版发布器**（新增 scripts/publish-gh-pages.sh）
   不依赖 Node 派发外部进程，更稳。deploy-once.ps1 优先用它，找不到 bash 才退回 .mjs。
   顺带修了自己引入的 bug：cd 到临时目录后相对路径失效，
   现在进目录前就把产物路径解析成绝对路径。
