# 如何把离线收益报告交给我

离线报告不在任何 HTTP 接口里，也不在客户端的全局变量里。它只在 **WebSocket 的 `welcome` 帧**中下发一次——也就是**每次登录时**。

所以只有三种拿法。

---

## 路径 A：我主动连一次（最省事，需共享 cookie）

**原理**：我用自己的客户端带上你的会话 cookie 连一次 `/ws`，这一次连接本身就算一次"登录"，服务端会把离线报告推给我。

**你要做的**：

1. 在游戏里正常玩，然后**关掉游戏标签页**，等待你想结算的那段时间（几小时/一晚）
2. 重新打开 <https://deepveinidle.com>，**先不要登录**
3. 按 `F12` → `Application`（应用程序）→ 左侧 `Cookies` → `https://deepveinidle.com`
4. 找到名为 **`sid`** 的那一行，双击 `Value` 列，全选复制
5. 把 `sid` 的值发给我

**我这边会执行**：

```bash
python dvi-offline-report.py "sid=<你给的值>"
```

输出是一份可读报告 + `offline-report.json`。

**⚠️ 三个必须知道的点**：

- **DVI 强制单会话**。我连接期间，你浏览器里的游戏会被踢下线，提示 `logged in elsewhere`。所以我连接时你**不要**在游戏里。
- **运行一次即消费**。离线进度结算完就没了，之后再打开游戏不会重复出报告。所以你给我的应该是"我还想看的那一次"。
- **cookie 有效期 30 天**，本身等同于账号凭证。它只用于读取你自己的游戏数据——但你自己要清楚这是共享凭据。**只想给我一次的话，用完在游戏里登出即可让 cookie 失效。**

---

## 路径 B：装用户脚本，自己导出（不共享凭据，推荐）

**原理**：脚本在**你自己的浏览器**里劫持收包，捕获 `welcome.offline`，然后由你决定把 JSON 给谁。

**你要做的**：

1. 打开 Tampermonkey → 新建脚本 → 把 `dvi-offline-capture.user.js` 的内容整个粘进去 → 保存
2. 正常玩、正常关标签页、离线一段时间
3. 重新打开游戏页面 —— 右下角会自动弹出一个面板
4. 点**「复制 JSON」**或**「下载 JSON」**，把结果发给我

**这个脚本做了什么**：

- 劫持 `MessageEvent.prototype.data` 的 getter（和 MWI 生态那批脚本同一手法），**不修改游戏代码、不替换 `window.WebSocket`、不发送任何游戏指令**
- 只读，捕获到报告就停下，不做别的事
- 控制台里也会同步打印一份 JSON，方便直接复制

**为什么浏览器里不需要处理 WebSocket 分片**：浏览器在触发 `onmessage` 前已经帮你把分片拼好了。分片重组只有写裸 socket 客户端时才需要操心（那是路径 A 的脚本要处理的事）。

---

## 路径 C：控制台手动 hook（不想装脚本的临时办法）

在登录**之前**粘贴到控制台：

```js
const d = Object.getOwnPropertyDescriptor(MessageEvent.prototype, 'data');
const g = d.get;
d.get = function () {
  const raw = g.call(this);
  try {
    const f = JSON.parse(raw);
    f?.m?.forEach(x => x.t === 'welcome' && x.offline &&
      console.log('[离线报告]', JSON.stringify(x.offline, null, 1)));
  } catch (e) {}
  return raw;
};
Object.defineProperty(MessageEvent.prototype, 'data', d);
console.log('已挂载，现在刷新页面并重新登录');
```

然后**刷新页面并重新登录** —— `welcome` 会重新下发，报告会打印在控制台。

**缺点**：控制台代码在页面刷新后就没了，所以必须"先粘贴、再刷新"。想省这个麻烦就用路径 B。

## 我拿到报告后能做什么

报告里有这些字段（实测样本）：

```json
{
  "ticksElapsed": 329,          // 离线总时长（≈秒）
  "ticksApplied": 329,          // 实际结算的时长
  "ticksSkipped": 0,            // 超出上限被丢弃的时长
  "skills": { "mining": { "xp": 110, "levelBefore": 6, "levelAfter": 7 } },
  "itemsGained": { "1": 51, "1001": 2 },   // itemId → 数量
  "deposits": 2,                // 自动存入仓库次数
  "drops": 0, "bonuses": 0, "burnt": 0,
  "kills": 0, "deaths": 0, "coins": 0,
  "stoppedEarly": false,        // 是否因背包满/缺料提前停止
  "segments": [                 // 分段明细：中途换了任务会有多段
    { "task": { "kind": "job", "jobId": 1 },
      "ticks": 329, "xp": { "mining": 110 },
      "items": { "1": 51, "1001": 2 }, "end": "running" }
  ]
}
```

配合已经提取的游戏数据（`gamedata/dvi-gamedata.json`），这些 id 都能翻译成名字——
`itemId 1` = Copper，`jobId 1` = 挖矿。所以我能算出**"这一觉赚了多少钱"**这类结论。

**顺便能校准的两个未知**：真实玩家的 `skills` 和 `itemsGained` 能反推出**每秒实际产出速率**，
正好可以用来验证上一轮还原的耗时公式（并补上装备品质加成、精通系数那两张缺失的数值表）。

---

## 建议

- **只是想让我分析一次** → 路径 A，快。
- **打算长期一起做这个脚本** → 路径 B，一次装好，以后每次登录都能自动捕获，还能顺便当成脚本的第一个模块。
- **只想试一下** → 路径 C。
