# DVI 静默数据采集 —— 安装说明

目标：**你看不见它**，但数据会自动落到本机文件里，我随时能读。

```
浏览器（用户脚本）  ──POST──▶  本机接收端  ──▶  captured/dvi-capture.jsonl
     ↓ 劫持收包                                        ↓
  只取你自己的数据                                我直接读这个文件
```

---

## 一次性安装（3 步）

### 1. 打开接收端

在本目录下开一个终端，运行：

```bash
python dvi-capture-server.py
```

看到 `等待用户脚本上报…` 就成了。**这个窗口要一直开着**（它就是我读数据的入口）。

首次运行时可以顺便验证一下：浏览器访问 <http://127.0.0.1:8787/health>，应该返回一段 JSON。

### 2. 装用户脚本

Tampermonkey → 添加新脚本 → 把 `dvi-collector.user.js` 的内容整个粘进去 → `Ctrl+S` 保存。

### 3. 正常玩

打开游戏、正常游玩、正常关闭。**不需要点任何东西，也不会有任何弹窗。**

## 它采什么、不采什么

| 采集 | 不采集（源头丢弃，永不落盘） |
|---|---|
| 离线收益报告（完整） | 聊天 / 世界频道 / 中文频道 |
| 你自己的存档快照（技能、装备、仓库、房屋、特长、精通…） | 私聊（whispers） |
| 出产速率（每 30 秒滚动汇总一次产出） | 公会聊天 |
| 市场盘口与最近成交 | 其他玩家的任何信息 |
| 世界状态（在线人数、种子、版本号） | 聊天内容长度以外的一切社交数据 |

**为什么这么设计**：你说过要"推己及人"——将来数据可能要分享出去换算法验证。所以从第一天就按**可分享**的标准采集：只包含你自己的角色数据，和完全匿名的聚合值。角色名之外还额外生成了一个 `pseudonym` 字段（角色 ID 的哈希），分享时用它可以彻底去标识化。

另外，脚本里对采集字段用的是**白名单**而不是黑名单。游戏以后新增字段时，不会被误采进来。

## 怎么确认它在工作（可选）

平时它完全静默。想确认的话，点浏览器工具栏的 Tampermonkey 图标，菜单里有四条命令：

- **📊 查看采集状态** —— 已上报多少条、有没有卡住
- **⏸ 暂停 / 恢复采集**
- **📤 立即上报**
- **🗑 清空本地缓冲**

按 `F12` 打开控制台也能看到每 15 秒一次的上报日志。

## 两个设计细节

**用 `GM_xmlhttpRequest` 而不是 `fetch`**
从 HTTPS 网页直连 `http://127.0.0.1` 会被 Chrome 的私有网络访问（PNA）策略拦住，需要服务端配合一堆预检头。走油猴的扩展级请求完全绕过这些限制——接收端里那段 PNA 头只是给"万一想用 fetch"留的后路。

**接收端没开也不会丢数据**
脚本会先把记录存在油猴本地存储里（上限 400 条），每 15 秒尝试补送一次。所以你可以先玩游戏、之后再开接收端，数据会自己追上。

## 常见问题

**数据没进来？**
先看终端窗口有没有 `收到 N 条记录`。没有的话，点油猴菜单的「查看采集状态」，看「失败重试」次数——如果一直在涨，说明接收端没开或端口被占用。

**换端口？**
`python dvi-capture-server.py --port 9000`，同时把脚本里的 `ENDPOINT` 改成对应端口。

**数据存在哪？**
`dvi_probe/captured/`：
- `dvi-capture.jsonl` —— 追加式全量记录（我读这个）
- `latest-self.json` —— 最近一次角色快照（人也能直接看）
- `latest-offline.json` —— 最近一次离线报告
- `capture-log.txt` —— 运行日志

**想彻底停掉？**
关掉终端窗口。游戏侧的脚本这时会自动转入本地缓冲，不会报错、不会打扰你。
